# Паспорт задачи: встроенный ZeroTier (libzt) в Android-приложение

## Критические требования ТЗ (дословно)
- «делай вариант 3» — встроить ZeroTier в приложение через libzt (ZeroTier
  Sockets, userspace, БЕЗ занятия VPN-слота Android), чтобы Hiddify и связь
  с ПК работали одновременно.
- «постарайся оптимизировать потребление батареи».

## Архитектурные решения
- Узел ZT живёт в процессе приложения (libzt/JNI), система VPN не трогается.
- **Батарея:** узел запускается лениво (при первой команде), останавливается
  по таймеру простоя (60 с после последней команды). Постоянного узла нет.
- Выбор транспорта в TcpCommandClient: если локальный интерфейс уже имеет
  адрес в подсети ПК (официальное ZT-приложение активно или LAN) — обычный
  Socket; иначе — ZeroTierSocket через встроенный узел.
- Identity узла — персистентно в filesDir/zt (авторизуется один раз).
- Network ID: новое поле `ztnet` в QR-профиле (трей читает
  ~/.config/rfid-agent/zt-network) + PcProfile.ztNetworkId (Room v4→v5).
- Новый узел приложения нужно **авторизовать на контроллере** (самохост,
  <IP контроллера ZT>) — действие пользователя; node id показываем в Настройках.

## РАБОТАЕТ (2026-08-29, вечер)
- Узел <node-id> авторизован пользователем; двух багов стоило довести:
  1) SIGSEGV: zts_moon_orbit до готовности нативного узла (start() асинхронный,
     NodeService::orbit не проверяет _node) → orbit только после isOnline.
  2) Rendezvous не проходил: у libzt 1.12 устаревший встроенный planet, а
     скачать moon-описание с seed нельзя без живых корней (яйцо-курица).
     Решение: **кастомный planet = moon-файл с байтом типа 127→1**, кладётся
     в storage узла как кэш `roots` ДО старта; мир с чужим id не затирается
     дефолтным. Корень встроенного узла = свой moon-сервер (<IP moon-сервера>).
- Доставка: QR-поле `ztroots` (base64 blob, трей читает
  ~/.config/rfid-agent/zt-roots) + `ztnet`/`ztmoon`; профиль Room v7;
  ZtEmbedded.installRoots() пишет blob в storage. QR ~586 символов — сканируется.
- Замеры (OnePlus 15, Wi-Fi): холодный старт до онлайна 5.3 с, до ответа
  команды 6–7.5 с; тёплая команда ~350 мс; idle-stop через 60 с подтверждён.
  ПК↔встроенный узел: DIRECT 28 мс (LAN). LOCK/UNLOCK/статус проверены.

## Смена сети (Wi-Fi ↔ LTE), 2026-08-29 поздно вечером
- Симптом «не работает после ухода с Wi-Fi»: протухшие пути в кэше пиров +
  первая попытка connect до завершения rendezvous. Фиксы: peer cache OFF,
  один автоповтор connect, окно простоя узла 60 с → 5 мин.
- Замер LTE: холодный первый connect ~30–40 с (NAT-обход через moon —
  неустранимая цена пути), дальше мгновенно. Проверено: STATUS/LOCK/UNLOCK
  с LTE; ПК видит узел DIRECT через <публичный IP телефона> (CGNAT пробит).

## Открытые вопросы / риски
- При активном Hiddify VPN трафик встроенного узла заворачивается в Hiddify —
  нужно исключить приложение в per-app настройках Hiddify (не проверено с
  активным Hiddify; без него всё работает).
- AAR только arm64-v8a — для публикации добавить armeabi-v7a при необходимости.
- Пересканирование QR обновляет ztroots при смене moon-сервера.
