# Паспорт задачи: встроенный ZeroTier (libzt) в Android-приложение

## Критические требования ТЗ (дословно)
- «делай вариант 3» — встроить ZeroTier в приложение через libzt (ZeroTier
  Sockets, userspace, БЕЗ занятия VPN-слота Android), чтобы Hiddify и связь
  с ПК работали одновременно.
- «постарайся оптимизировать потребление батареи».

## Архитектурные решения
- Узел ZT живёт в процессе приложения (libzt/JNI), система VPN не трогается.
- **Батарея:** узел запускается лениво (при первой команде), останавливается
  по таймеру простоя (60 с после последней команды). Постоянного узла нет.
- Выбор транспорта в TcpCommandClient: если локальный интерфейс уже имеет
  адрес в подсети ПК (официальное ZT-приложение активно или LAN) — обычный
  Socket; иначе — ZeroTierSocket через встроенный узел.
- Identity узла — персистентно в filesDir/zt (авторизуется один раз).
- Network ID: новое поле `ztnet` в QR-профиле (трей читает
  ~/.config/rfid-agent/zt-network) + PcProfile.ztNetworkId (Room v4→v5).
- Новый узел приложения нужно **авторизовать на контроллере** (самохост,
  <IP контроллера ZT>) — действие пользователя; node id показываем в Настройках.

## Состояние
- libzt в Maven Central отсутствует → сборка AAR из исходников
  (github.com/zerotier/libzt, ports/android), NDK 26 + CMake через sdkmanager.
- Сеть: <zt-сеть> <zt-network-id>; ПК <ZT-IP ПК1>:5390; телефон OnePlus 15.

## Сделано (2026-08-29)
- AAR собран из libzt (pkg/android, NDK 25.1, JDK 17, только arm64-v8a;
  лежит в android-app/app/libs/libzt-release.aar, в git).
- ZtEmbedded.kt: ленивый узел (acquire/release, idle-stop 60 с, кэши libzt
  включены для быстрого повторного старта), identity в filesDir/zt.
- TcpCommandClient: выбор транспорта — прямой Socket, если есть интерфейс
  в /24 ПК (системный ZT/LAN), иначе ZeroTierSocket через встроенный узел.
- PcProfile.ztNetworkId (Room v4→v5) + QR-поле ztnet (трей читает
  ~/.config/rfid-agent/zt-network; на этом ПК записано <zt-network-id>).
- SettingsScreen показывает node id встроенного узла.
- Проверено на OnePlus 15 (системный ZT выключался): узел стартует, онлайн,
  join сети, честная ошибка «узел <node-id> авторизован на контроллере?».
  Identity создана, node id стабилен: **<node-id>**.

## СЛЕДУЮЩИЙ ШАГ
- Пользователь авторизует узел <node-id> на контроллере <zt-сеть>
  (<zt-network-id>, самохост) → повторить команду при активном Hiddify
  (решающий тест) и замерить холодный старт.

## Открытые вопросы / риски
- Время холодного старта в реальной сети (корни за блокировками) — замерить
  после авторизации; при >5–10 с поднять окно простоя или предпрогрев.
- AAR только arm64-v8a — для публикации добавить armeabi-v7a/x86_64 при
  необходимости (пересборка с другими abiFilters).
